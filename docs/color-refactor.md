# 配色重构：从「能看」到「可读 + 可证」

> 版本 1.36.1 · 对应审计报告 `docs/color-audit.html`
> 一句话：把「颜色好不好看」的问题，改成「颜色有没有职责」的问题——每枚令牌只有一个职责、一个对比度门槛，并写进 `npm test`。

## 二、令牌模型：10 枚职责重叠 → 12 枚单一职责

**改造前**（问题根源：同一枚令牌在 A 处当图形色、B 处当文字色）

```
accent（浅色主题 = 正文黑）+ panelAccent（固定红）  → 两套"高亮"语义
muted  #RRGGBBAA                                    → 文字色带 alpha，实际对比度无法预估
chromeBorder                                        → 同时当"装饰分隔线"和"输入框边界"
（无）                                              → 阴影/删除色/Logo 只能硬编码
```

**改造后**

| 令牌 | 职责 | 硬约束 |
|---|---|---|
| `bg` | 正文纸面 | — |
| `fg` | 正文 / 一级文字 | 对 `bg` ≥ 7:1 |
| `pageBg` | 纸面外留白；控件底、选中底 | 对 `bg` ≥ 1.15:1（预设 ≥1.25） |
| `chromeBg` | 侧栏 / 状态栏 / 面板底 | 对 `bg` ≥ 1.05:1 |
| `chromeBorder` | **装饰**分隔线、面板软边 | ≈1.55:1（只求可见，不承担识别） |
| `borderStrong` | **控件边界**：输入框/按钮/色点/进度槽 | 对 `chromeBg` ≥ 3:1（WCAG 1.4.11） |
| `accent` | 高亮文字 + 按钮底 + 图标 + 焦点框 | 对 `pageBg` ≥ 4.5:1（文字级）；对 `chromeBg` ≥ 4.5:1 |
| `accentFg` | 强调色上的文字 | 对 `accent` ≥ 4.5:1 |
| `muted` | 次要文字（实色） | 对 `chromeBg` ≥ 4.5:1 |
| `panelHover` | 悬停底色 | 肉眼可辨即可 |
| `danger` | 删除等危险操作 | 对 `bg` ≥ 4.5:1 |
| `shadow` | 纸面/浮层/按钮投影 | 深色主题必须加重 |

> 关键决定：**强调色只保留一枚**。原先"高亮文字用 accent、选中态用 panelAccent"是两套语言，用户无法建立"这个颜色＝当前"的预期。现在目录当前章、侧栏激活项、进度条、滚动条、焦点框、主按钮全部同色。

### 4.1 五层结构

```
┌ L3 浮层（目录/设置/书架/存储）   bg + 1px chromeBorder + --shadow-color
├ L2 留白区（正文四周）           pageBg        ← 最深的一层"底"
```

### 4.4 派生主题（省 / 节气）算法

```ts
// 只借色相，明度与饱和度全部锁定；所有校准都指向"最差底色"
bg           = hsl(h, .26, .925)
chromeBg     = hsl(h, .24, .895)          // 比纸面深一档
pageBg       = hsl(h, .30, .830)          // 再深一档
chromeBorder = ensure(hsl(h,.32,.76), chromeBg, 1.55)
borderStrong = ensure(hsl(h,.30,.60), chromeBg, 3.0)
fg           = hsl(h, .32, .16)
muted        = ensure(hsl(h,.12,.44), chromeBg, 4.5)
accent       = ensure(代表色, pageBg, 4.5) // 关键：不是 bg
accentFg     = white-on-accent ≥4.5 ? #fff : #191919
danger       = ensure(#b3261e, bg, 4.5)
```

`ensure()` 现在会**自动判断方向**：底色偏暗就提亮、偏亮就压暗。旧实现只会压暗——派生主题目前全是浅色，暂时没暴露问题，但一旦接入深色派生（夜间节日、深色省份），边框会被一路压到近黑而不可见。顺手改掉，避免以后再踩。

新增的关键断言（就是这次缺陷的"回归线"）：

```js
// 强调色两处最差底色都要达标
contrastRatio(t.accent, t.pageBg)   >= 4.5   // 当文字
contrastRatio(t.accent, t.chromeBg) >= 4.5   // 当图标
contrastRatio(t.accentFg, t.accent) >= 4.5   // 反白（原先是 3）
contrastRatio(t.muted, t.chromeBg)  >= 4.5   // 次要文字（原先用 bg，漏了更暗的面板）
contrastRatio(t.borderStrong, t.chromeBg) >= 3
contrastRatio(t.bg, t.chromeBg) >= 1.05 && contrastRatio(t.chromeBg, t.pageBg) >= 1.08
// 强调色不得等于正文色（旧版浅色主题如此）
assert.notStrictEqual(t.accent, t.fg)
// 8 位 hex 必须按 alpha 合成，而不是被当成黑色
assert(Math.abs(contrastRatio('#00000080','#fff') - contrastRatio('#808080','#fff')) < 0.15)
```

### 5.2 手动（`npm run dev` → `http://localhost:5200/webview/reader/dev.html`）

按六套主题各看一遍，重点四处：

1. **侧栏 + 正文**：纸面/留白/侧栏三层能一眼分开；Logo 三色不糊。

## 七、取舍与遗留

1. **Logo 让位主题色**：品牌橙 `#ED8F27` 不再固定，改为「书封＝强调色、线稿＝正文色、书页＝纸面色」。好处是任何主题下都可读；代价是失去橙色识别。若要保留品牌，可把 `--accent` 单独再拆一枚 `--brand`（仅 Logo 用），但会破坏"一套强调色"的规则，不建议。
2. **浮层与纸面同色**：弹窗底用 `bg`，与正文纸面完全同色，靠阴影 + 软边区分。当前可接受；若后续觉得"糊"，可让弹窗改用 `chromeBg`。
3. **浅色主题的强调色偏深**：为了 4.5:1，朱红/赭石都被压暗了一档，比"中国红"更沉。这是可读性优先的必然结果；若要做海报主视觉，用原色（`docs/festival-colors.html` 里的主色），不要用阅读主题的 `accent`。
4. **`isDark` 只用于方向判断**：目前没有按 `isDark` 分支的样式，保留字段是为了未来加"夜间自动切换"时不用再改类型。
5. **v1.36.1 取色微调（只调色值，不动令牌模型）**：① `accent` 让强调色更贴近中国色本相——米白由 `#845629` 转为更红润的赭 `#8c4423`、羊皮纸由 `#864929` 转为 `#8d3f22`、黑夜由 `#c9963f` 提亮为更亮的暖金 `#d8a84e`（纯净白朱红 `#b83729`、护眼绿墨绿 `#2b6135`、浅蓝靛 `#2c5a8a` 保持不变）；② `danger` 原值与白色主题的朱红强调色几乎同色（`#b3261e` vs `#b83729`），"危险"与"当前"语义冲突，统一压深一档为 `#8f1d16`（羊皮纸/绿/蓝为 `#8c1d18`），形成"危险＝更沉的绛红"，与 `accent` 拉开区分度；黑夜的浅红 `#ff9d93` 保持不动。所有门槛（强调/pageBg、强调/chromeBg、反白/accent、危险/bg 及台阶）继续全部通过，门槛值本身未做任何放宽。
