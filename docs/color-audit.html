01结论

色彩模型本身是干净的：10 个语义令牌驱动全部界面，58 套主题零 CSS 分支。问题不在颜色好不好看，而在令牌角色重叠与校准目标用错——同一枚令牌在 A 处当图标色（3:1 够）、在 B 处当正文色（需 4.5:1），于是大面积低估。

① 双强调色并行。浅色 5 套主题里 accent 等于正文色（无彩黑），panelAccent 固定为品牌红 #f56c6c。于是“当前项”这一语义在不同部位换成两种颜色：目录当前章用黑、侧栏激活项用红、书架当前书用黑条、省份选中项用红底。

② 可读性系统性偏低。11–12px 次要文字全部落在 3.07–4.12:1；红色强调在纸面上仅 2.31–2.90:1；58 套派生主题中 38 套的强调色作文字时 <4.5:1。

③ 层次靠 1.1:1 的底色差撑。纸面 / 留白 / 侧栏三层底色对比 1.04–1.17，边线 1.19–1.38，均低于 3:1 的界面元素可辨阈值。

06三个维度的问题

一致性

01

两套强调色并行，同一语义两种颜色

accent（浅色下＝正文黑）与 panelAccent（红）同时承担“选中/当前”语义。目录当前章是黑，侧栏激活是红，书架当前书是黑边条，省份选中是红底 —— 用户无法建立“高亮＝某一种颜色”的稳定预期。

02

品牌红不跟随主题

#f56c6c 硬写在 5 套浅色主题里。切到护眼绿/浅蓝时，红点、红进度条、红焦点框与整体色相冲突，看起来像“主题没生效”。

03

同一令牌在不同作用域含义不同

--sp-bg 在根元素＝chromeBg，在浮层内被覆写为 bg；--sp-control-bg 根＝bg、浮层内＝page-bg。同名不同义，后续加组件极易取错。

04

次要文字两套降级机制

一边有 --sp-muted（3 处），一边用 opacity: .35/.55/.6/.65/.7/.85 共 30 处。透明度叠加在深浅底上结果不可控，也无法参与对比度校验。

可读性

05

小字全部低于 AA

11–12px 的卷名、字数、路径提示、快捷键说明，在 6 套主题下只有 3.07–4.12:1。羊皮纸最差（3.07），护眼绿次之（3.21）。

06

强调色校准目标用错

paintTheme 给 panelAccent 只校到 3:1，但它在 CSS 里是侧栏激活文字、目录当前章文字、分段键文字 —— 都属正文级。38/58 套因此不达标。

07

强调色只对纸面校准，漏掉选中底

目录当前章的文字压在 page-bg 上（比纸面更深），而对比度只按 bg 算过。48/58 套在真实组合下 <4.5。

08

红底白字不成立

省份/节气下拉选中项用 --sp-accent 底 + --sp-accent-fg，但该变量从未定义，永远落到 #fff；白字在 #f56c6c 上仅 2.90:1。

09

删除按钮红越界

#d9534f 不属于任何主题色板，3.16–3.97:1；同时也让“红＝危险”与“红＝强调”在同一界面里打架。

视觉层次

10

三层背景几乎同色

纸面 / 留白 / 侧栏：白 1.11 / 1.07 / 1.06，羊皮纸 1.13 / 1.05 / 1.05。层次全靠 1px 边线，而边线本身也只有 1.19–1.38:1。

11

阴影在黑夜主题失效

5 档黑色投影没有主题化。#1c1c1c 底上叠 rgba(0,0,0,.25) 几乎无变化，浮层与纸面之间失去高度差，只剩边线可用 —— 而边线也不到 1.4:1。

12

Logo 在多数主题下“半消失”

米白书页在浅色侧栏 1.02–1.16:1，橙色块 1.84–2.29:1；深棕线稿在黑夜 1.07:1。只有 .logo-spark 做了 dark 分支，其余 6 个 path 硬编码。

13

进度条槽＝边线色

.progress-track 直接复用 --chrome-border，1.19–1.35:1；未填充段几乎不可见，进度条的“总量”信息丢失。

14

58 套主题只产出 25 种纸面色

同色相在 8bit 下被量化重合（测试里也承认“34 省实际只能区分 ~17 种”）。切换省份/节气时，正文区和纸面看不出变化，地域辨识度实际由留白区独自承担。

07优化建议

P0 · 先把“错误的校准”修掉（改动最小，收益最大）

  • paintTheme 中 panelAccent 的校准目标 3 → 4.5；accentFg 的判据 3 → 4.5。
  • 新增一次对 page-bg 的校准：accentText = ensureContrast(accent, pageBg, 4.5)，专门供“选中底上的文字”使用（目录当前章、分段键激活态）。
  • 补上 --sp-accent-fg 的定义（accentFg），去掉 #fff fallback。
  • 把 contrastRatio() 的解析改成支持 8 位十六进制并做 alpha 合成，否则 muted 永远是假通过。
  • 测试补三条断言：panelAccent/chromeBg、accent/pageBg、muted 合成后/bg。

P1 · 统一强调色：一套颜色，两个强度

取消“固定品牌红”，让强调色回到主题自己的色相；用强度区分用途，而不是用两枚不相干的颜色：

P1 · 次要文字改成实色，别再叠透明度

把 opacity: .55/.6 全部替换为一枚计算好的 --fg-muted（实色，保证 4.5:1）。6 套主题的建议值：

P1 · 重建三级背景台阶

目标：纸面 → 留白 ≥1.25、浮层 → 留白 ≥1.15；需要用户识别的控件边界 ≥3:1，纯装饰分隔线可以放宽。以纯净白为例：

  • 纸面 #ffffff（不变）
  • 留白 #f3f3f3 → #e8e4dd（对比 1.27，带一点暖灰）
  • 侧栏/浮层 #f7f7f7 → #f1efe9（对纸面 1.15、对留白 1.12）
  • 边线 #e4e4e4 → 装饰分隔 #cfcac0（1.63）；输入框/按钮/浮层外框 #968f85（3.20）

派生主题同步调整 paintTheme：pageBg 明度 0.85 → 0.83、chromeBg 0.915 → 0.90，即可让三层在 58 套主题里都拉开距离，同时不破坏“同色相”的地域感。

P2 · 阴影、Logo、硬编码色收进主题

  • 阴影改为 --shadow-color：浅色 rgba(0,0,0,.10)，黑夜 rgba(0,0,0,.55) 且额外加 1px 顶部亮边；统一 3 档（浮层 32/按钮 8/纸面 16）。
  • Logo 三色提炼为品牌令牌 --brand-1/2/3，并提供 light/dark 两组值：浅色底用“深棕 + 橙”、隐藏米白或改成描边；黑夜底用“米白 + 橙”。不要把 6 个 path 写死。
  • 删除按钮改用 --danger（如 #b3261e，在纸面 6.54:1），与强调色共享色相规则但保留语义区分。
  • 进度条槽改用 --page-bg 或 --fg-muted 的低透明度版本，别再用边线色。

P2 · 结构清理

  • 删除死令牌 --btn-hover（定义 0 使用）；--fab-* 重命名为 --nav-btn-*（现已不含悬浮球）。
  • --sp-bg 的浮层覆写改为独立令牌（如 --panel-bg），避免同名不同义。
  • 主题色点对 dark 的 #1c1c1c 硬编码改为读 chromeBg。
  • 为“主题辨识度”加回归阈值：任意两套主题的 pageBg ΔL ≥ 0.03，或至少在主题按钮上常驻显示色名，弥补 25/58 的量化撞色。
