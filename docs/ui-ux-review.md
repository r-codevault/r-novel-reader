# 小说阅读器 UI/UX 设计评审与改造方案

- **项目**：r-novel-reader
- **评审版本**：v1.48.7
- **文档日期**：2026-10-25
- **评审范围**：阅读页、书架、目录、笔记、阅读设置、书源管理、历史记录、存储位置及关键扩展交互链路
- **评审依据**：当前 Vue/CSS/TypeScript 源码、`docs/images` 界面截图、关键状态色对比度复算
- **评审限制**：本次为静态设计评审，未在 VS Code 扩展宿主中完成所有尺寸、主题和异步时序的实机回归

## 1. 总体结论

项目不需要推倒重做。现有“左侧导航—居中纸面—底部状态栏”的布局符合长时间阅读场景，正文仍是视觉中心；进度恢复、章节加载骨架、失败重试、笔记返回原位置等设计也保证了基本阅读连续性。

当前主要问题不是视觉风格，而是以下四类体验基础仍需补齐：

1. **键盘主链路不完整**：目录、书架、历史、搜索和笔记等核心任务仍偏鼠标化。
2. **浮层与响应式基础不稳固**：焦点没有随浮层交接，窄屏、矮屏存在内容裁切。
3. **关键流程缺少一致终态**：危险操作、异步失败、搜索诊断和设置预览的收尾规则不统一。
4. **部分状态色和小控件未达到可读、可操作基线**：深色危险按钮和浅色成功状态尤其明显。

建议保留现有阅读架构和主题体系，优先修复交互与可访问性，再做视觉密度优化。

## 2. 现有设计优点

### 2.1 布局结构

- 左侧导航参与文档流，正文居中，底部状态栏固定，阅读位置明确。
- 书架、目录、设置、书源等采用统一浮层语言，并通过互斥规则避免多面板同时打开。
- 正文纸张、侧栏和留白采用分层背景，章节导航与阅读进度位置稳定。
- 浮层列表具备滚动隔离，降低滚动穿透对正文阅读位置的干扰。

### 2.2 阅读体验

- 具备章内位置恢复、加载骨架、错误重试和空状态。
- 笔记支持定位原文及返回上次阅读位置，形成较完整的上下文恢复链路。
- 在线搜索提供暂停、继续、取消和分批结果，基础任务控制能力较完整。

### 2.3 视觉与主题

- 已建立语义主题令牌及预设、地域、节气、节日主题。
- 已有主题对比度自动测试，可在此基础上补充遗漏的“状态色作为背景”测试。
- 骨架动画已考虑 `prefers-reduced-motion`，可继续覆盖其他非必要动效。

## 3. 优先级定义

| 优先级 | 定义 | 处理原则 |
| --- | --- | --- |
| P0 | 主流程不可用，或可能造成正文、进度、状态错乱 | 优先修复并补自动化回归 |
| P1 | 高频操作存在明显障碍、数据风险或可读性问题 | 在下一轮界面改造中完成 |
| P2 | 操作效率、视觉层级、触控和一致性不足 | 统一组件和设计参数时收敛 |

## 5. 详细问题与可执行修改方案

### 5.1 P0：键盘无法完成多条核心任务

**问题证据**

- `webview/reader/components/CatalogPanel.vue:305-326`：分卷和章节使用可点击 `div`。
- `webview/reader/components/ShelfPopup.vue:119-137`：书籍条目和删除入口不可键盘操作。
- `webview/reader/components/HistoryPopup.vue:151-162`：历史条目只有点击事件。
- `webview/reader/components/SourceSearchView.vue:341-370`：搜索结果整行预览依赖点击。
- `webview/reader/components/ReaderArea.vue:367-369`：段落笔记只监听鼠标事件。
- `webview/reader/components/NotesPopup.vue:336-400`：分组按钮内嵌其他交互角色，笔记条目本身不可聚焦。

**用户影响**

键盘用户无法可靠完成打开书籍、目录跳章、搜索预览、新建笔记和笔记管理。嵌套交互控件还会导致 Enter、Space 和屏幕阅读器行为不一致。

**修改方案**

1. 单一主动作的条目改为原生 `<button type="button">`，保留现有行样式。
2. 含多个动作的条目采用“行容器＋独立主按钮＋操作按钮组”，不要把按钮嵌进按钮。
3. 当前书、当前章补 `aria-current`；分卷展开按钮补 `aria-expanded` 和 `aria-controls`。
4. 段落提供独立的“添加/查看笔记”按钮，并增加不依赖鼠标的快捷键入口。
5. 不建议简单给所有正文段落添加 `tabindex="0"`，否则会产生大量低效率 Tab 停靠点。
6. 笔记组头拆成并列的展开按钮、原生复选框和删除按钮；半选状态使用原生 `indeterminate` 或 `aria-checked="mixed"`。

**验收标准**

仅使用键盘即可完成“打开书籍 → 目录跳章 → 搜索预览 → 新建笔记 → 编辑并保存笔记”。

### 5.2 P0：异步结果缺少书籍归属，可能出现串书

**问题证据**

- `src/readerPanel.ts:1377-1405`：在线章节请求结束后重新读取可变的 `this._novel`，迟到响应可能写入后来打开的书。
- `src/extension.ts:457-520`：下载进度和结果在发往 Webview 时缺少完整书籍归属。
- `webview/reader/App.vue:452-496`：前端可能把后台任务状态合并到当前书。

**用户影响**

快速切书或弱网环境下，可能出现“书名是 B、正文却是 A”，或者 B 书显示 A 书的下载进度、按钮状态和完成通知。

**修改方案**

1. 请求开始前捕获 `const novel = this._novel`，结果只能写回该对象。
2. 为打开书籍、章节加载、在线预览和下载引入 `requestId/generation`。
3. `chapter`、`chapterCached`、`chapterError`、`downloadProgress`、`downloadDone` 全链路携带 `filePath/key`。
4. 前端只接受当前任务或当前书籍的回包；后台任务进度进入独立任务表，不直接污染当前界面。
5. 加载锁按请求实例清理，不能仅按章号删除另一轮请求的锁。
6. 暂停、继续、取消下载也显式携带目标任务 `key`，不依赖“当前书”。

**验收标准**

A 书章节请求或下载处于进行中时切换到 B 书，A 的迟到回包不得改变 B 的正文、缓存点、下载进度和通知。

### 5.3 P1：窄屏和矮屏存在不可达裁切

**问题证据**

- `webview/reader/reader.css:540-559`：浮层固定 `min-width:380px` 会覆盖较小的响应式 `max-width`。
- `reader.css:480-492`：侧栏 `height:100vh; overflow:hidden`，内容过高时底部入口不可达。
- `reader.css:35-59`：目录工具区不换行，窄屏时末尾操作容易溢出。
- `reader.css:967-983`：搜索父级隐藏溢出，结果区又按固定行高分配，矮屏时内容可能永久被裁切。

以 400px 视口、48px 侧栏为例：浮层左缘为 64px，最小宽度仍为 380px，右缘达到 444px，至少 44px 位于视口外。

**修改方案**

统一浮层可用宽度，不再让固定最小宽度覆盖视口约束：

```css
#shelfPopup,
#storagePopup,
#notesPopup,
#sourcePopup,
#historyPopup {
  width: min(560px, calc(100vw - var(--menu-w, 48px) - 32px));
  min-width: 0;
}
```

同时完成以下调整：

1. ≤576px 时浮层使用左右 8px 可用边距，目录标题和工具区分两行，关闭按钮独立固定。
2. 侧栏改为 `overflow-y:auto; overflow-x:hidden`，必要时将品牌区固定、菜单列表滚动。
3. `.src-results` 改为 `flex:1 1 auto; min-height:0`，在剩余高度内分配本次结果和历史结果。
4. 小高度下减少结果行数，或允许整个搜索体纵向滚动。
5. 目录“上一章/下一章”等次级动作在窄屏移至底部或折叠菜单。

### 5.4 P1：正文字号与 UI 字号耦合

**问题证据**

- `reader.css:4-9`：UI 字号由正文 `--font-size` 推导，正文增大时界面文字同步增大。
- `reader.css:923-927,1037-1040,1123-1128`：搜索结果和书源行仍采用固定高度。

**用户影响**

用户为阅读舒适而放大正文字体时，管理面板也会随之膨胀；固定行高无法同步适应，容易出现文字挤压和溢出。

**修改方案**

1. 将阅读字号与 UI 字号拆成独立变量。
2. 建议 UI 正文默认 14px、辅助文字 12px；如确有需求，再提供独立 UI 缩放设置。
3. 密集列表的固定 `height` 改为 `min-height`，允许内容自然增高。
4. 长书源名、书名和元信息使用明确的单行省略或双行换行策略。
5. 列表容量根据实际剩余空间和行高计算，不再假设所有行始终等高。

### 5.5 P1：浮层缺少语义、焦点交接和焦点恢复

**问题证据**

- `webview/reader/App.vue:72-75`：`openOnly()` 只切换布尔状态，不移动焦点。
- `App.vue:681-713`：Esc 关闭后主动 `blur()`，焦点丢到页面。
- 各浮层根节点主要是普通 `<section>`，标题使用 `<b>`，缺少可访问名称关联。

**修改方案**

1. 标题改为真实 `<h2 id>`。
2. 当前非模态浮层增加 `role="dialog" aria-modal="false" aria-labelledby`。
3. 打开前保存触发元素，`nextTick` 后聚焦标题、关闭按钮或首个主要控件。
4. 关闭后恢复触发点；由外部协议打开时使用合理 fallback。
5. 非模态浮层不必强行焦点圈禁；若未来改为模态，再增加焦点圈禁和背景 `inert`，不要混用两种模型。
6. Esc 优先关闭内部下拉，再次 Esc 才关闭整个面板。

### 5.6 P1：首次使用和续读入口存在错误引导

**问题证据**

- `src/extension.ts:1426-1440`：空书架执行书源搜索仍要求先打开本地书。
- `src/extension.ts:954-969`：项目已经实现可复用的空阅读页和书源空态。
- `src/extension.ts:1779-1790`：未读书无有效进度时，续读回退值可能为最后一章。

**修改方案**

1. `showSourcesPanel()` 直接进入现有 `openEmptyReader('source')` 或 `openDrawerAt('source')` 流程。
2. 首次用户无需先导入本地书，即可导入书源并在线搜索。
3. 无当前面板、无有效阅读进度时统一回退章节 `0`。
4. 增加“首次安装直接在线搜书”和“新增未读书续读到第 1 章”回归测试。

### 5.7 P1：危险操作的确认、取消和反馈不一致

**问题证据**

- `webview/reader/components/NotesPopup.vue:97-102`：批量删除笔记没有统一确认，选择态立即清空。
- `webview/reader/components/HistoryPopup.vue:71-76`：历史批量删除存在同类问题。
- `webview/reader/components/StoragePopup.vue:46-50`：清除本书离线内容缺少与“清全部”一致的确认。
- `src/extension.ts:1745-1775`：“刷新书架”还可能合并和清理记录，不仅是读取刷新。

**修改方案**

1. 建立统一确认组件，明确显示删除数量、涉及书/章、缓存大小和是否可恢复。
2. 等待成功回包后再退出管理模式；失败时保留选择、草稿和当前上下文。
3. 清除本书离线内容前，显示书名、章数和占用空间。
4. “刷新书架”先输出新增、合并、清理的预演清单，用户确认后再执行。
5. 目录或磁盘暂时不可访问时，不得直接等同于文件已删除并清理记录。
6. 无当前在线书或无离线内容时，禁用对应清除和导出按钮。

### 5.8 P1：设置主题预览可能残留，控件表达不完整

**问题证据**

- `webview/reader/components/SettingsPanel.vue:185-253`：主题预设是不可聚焦的色点 `span`，名称主要依赖 `title`。
- `SettingsPanel.vue:37-44`：只有省份下拉统一恢复主题，节气和节日缺少等价监听。
- `webview/reader/App.vue:694-707`：Esc 直接关闭设置面板，未先处理内部下拉和预览状态。
- `SettingsPanel.vue:304-323`：页面宽度直接暴露 `33.33%` 等工程参数。

**修改方案**

1. 色点改为具有可访问名称的单选按钮，补 `aria-checked` 和方向键导航。
2. 使用“名称＋色卡”或色卡下方可见名称，避免只能悬停才知道主题含义。
3. 统一监听三个下拉和 `settingsOpen`，关闭时全部 `restoreTheme()`。
4. 页面宽度改为“窄 / 标准 / 宽 / 特宽”，百分比作为辅助说明。
5. 自定义像素输入增加可见或屏幕阅读器可读的 `label`。
6. 用纯键盘路径验证“打开下拉 → 聚焦预览 → Esc → 重开设置”，不得残留未保存主题。

### 5.9 P1：加载、失败和保存状态缺少统一终态

**问题证据**

- `webview/reader/components/SourceSearchView.vue:311-339`：已有错误 `kind/message`，界面主要显示失败数量。
- `webview/reader/components/CatalogPanel.vue:297-300`：下载结果只在目录显示，其他面板操作时可能不可见。
- `webview/reader/components/NoteComposer.vue:144-146`：动态错误缺少明确播报语义。

**修改方案**

1. 增加可展开的失败明细：书源名、错误类型、精简原因和重试入口。
2. 区分“搜索成功但无结果”和“请求失败导致无结果”。
3. 普通进度使用 `role="status" aria-live="polite"`；最终失败使用 `role="alert"`，避免每次进度刷新都打断阅读。
4. 视觉进度条补 `role="progressbar"`、`aria-valuemin/max/now` 和名称。
5. 所有写操作统一为“操作中 → 成功/失败”回包，并携带操作 ID。
6. 结果提示在发起操作的面板内可见；失败时恢复按钮、保留草稿和选择。

### 5.10 P1：危险按钮和成功状态文字对比度不足

**问题证据与复算结果**

- `reader.css:676-680,941-945`：危险按钮和失效角标固定使用白字。
- `src/settings.ts:214-227`：深色主题危险色为 `#ff9d93`，白字对其对比度仅 **2.00:1**。
- `reader.css:1003,1140-1144`：成功状态使用 `--charts-green` 和固定回退色 `#2ea043`。
- `#2ea043` 在当前浅色弹窗背景上的对比度约 **2.50–2.96:1**，低于普通文字要求的 4.5:1。

**修改方案**

1. 新增 `dangerFg` 语义令牌。浅色主题可使用白字；深色主题可使用 `#191919`，后者对 `#ff9d93` 的实测对比度约 **8.79:1**。
2. 新增按各主题 `chromeBg` 校准的 `success`，不要直接依赖未经验证的 VS Code 图表色。
3. 将 `.popup-danger`、`.src-tab-num`、`.src-ok`、`.src-status.is-ok` 统一接入新令牌。
4. 在现有主题测试中增加以下组合，覆盖全部预设和派生主题：

```ts
contrastRatio(theme.dangerFg, theme.danger) >= 4.5;
contrastRatio(theme.success, theme.chromeBg) >= 4.5;
```

### 5.11 P2：书源和笔记操作层级密集，关键动作依赖悬停

**问题证据**

- `webview/reader/components/SourceManageView.vue:180-245`：导入、检查、导出、批量和筛选同时展开，视觉权重接近。
- `reader.css:1234-1248,1294-1300`：笔记分组删除和条目操作主要依赖 hover。
- `reader.css:1294-1300`：操作组使用 `display:none`，使键盘用户缺少首次进入操作组的路径。

**修改方案**

1. 书源保留一个主操作“导入书源”，URL、剪贴板、文件放入其子菜单。
2. “检查全部”为次操作，“导出”进入“更多”；批量条只在管理模式出现。
3. 危险操作与普通工具分区，避免与高频主操作并排。
4. 笔记增加可聚焦、触屏可见的“更多”按钮。
5. 操作组至少在 `:focus-within` 和粗指针环境可见，不依赖 hover 才能首次到达。
6. 保留现有点击定位原文的高频路径，同时为预览、编辑、删除提供明确独立入口。

### 5.12 P2：小控件和表单可访问名称不足

**问题证据**

- `reader.css:1131`：书源复选框为 13×13px。
- `reader.css:1146-1154`：书源图标按钮为 24×22px。
- `SourceManageView.vue:201-234`：多个输入主要依赖 placeholder，复选框名称未包含具体书源。
- 笔记新建和行内编辑的 `textarea` 也缺少明确标签。

**修改方案**

1. 以 **24×24 CSS px** 为最低目标，并检查目标间距例外；粗指针下提升至约 40–44px。
2. 使用 `<label>` 扩大复选框点击区域，不要让 13×13px 成为唯一点击目标。
3. 复选框生成“启用书源＋书源名”等独立名称。
4. 搜索、筛选、笔记和书源编辑输入补 `label/aria-label`；placeholder 只承担提示，不承担控件名称。
5. 图标按钮提供包含操作对象的 `aria-label`，例如“检查书源：起点”。

## 6. 建议统一的设计参数

| 类别 | 建议参数 |
| --- | --- |
| 布局间距 | 以 8px 为主要布局步进，4px 用于图标和文字间微调 |
| 浮层宽度 | 使用可用视口宽度约束，`min-width:0`，≤576px 左右留 8px |
| 响应式检查点 | 320、400、576、768、1200px；另测 360/480px 高度 |
| UI 字体 | 默认正文 14px、辅助文字 12px，与阅读字号解耦 |
| 阅读字体 | 保留用户 12–32px 设置，不反向撑破管理界面 |
| 桌面控件 | 主要按钮建议约 32px 高，紧凑图标不得影响 24×24px 最低目标要求 |
| 粗指针控件 | 点击区域约 40–44px，并保留足够目标间距 |
| 动效 | 约 160ms，仅动画 `transform` 和 `opacity`；减少动态效果时关闭非必要动画 |
| 状态反馈 | 统一 pending/success/error；错误在操作发起处可见，并支持辅助技术播报 |
| 主题令牌 | 保留现有语义体系，新增 `dangerFg`、`success` 并纳入自动测试 |

## 7. 推荐实施顺序

### 第一阶段：修复体验阻断

- 修复键盘主链路。
- 修复在线章节、预览和下载的请求归属与迟到回包处理。
- 补充 A/B 书切换的异步回归测试。

### 第二阶段：统一布局与核心流程

- 修复浮层宽度、矮屏滚动、目录工具条和搜索结果高度。
- 完成浮层语义、打开聚焦、关闭焦点恢复。
- 修复首次在线搜索和未读续读入口。
- 统一危险操作确认、异步终态和当前面板反馈。

### 第三阶段：收敛视觉与组件

- 拆分阅读字号和 UI 字号。
- 优化书源、笔记的信息层级和悬停依赖。
- 新增状态色令牌并补对比度测试。
- 统一触控目标、表单名称、Tab 状态和动效参数。

## 8. 验收清单

### 8.1 键盘与焦点

- [ ] 仅使用键盘可打开书籍、选择章节、预览搜索结果和加入书架。
- [ ] 仅使用键盘可创建、编辑、保存和删除笔记。
- [ ] 所有按钮、复选框和分组均有正确名称、角色和状态。
- [ ] 打开浮层后焦点进入浮层，关闭后回到触发入口。
- [ ] Esc 按内部下拉、浮层、侧栏的层级依次关闭，不出现焦点丢失。

### 8.2 响应式布局

- [ ] 在 320/400/576/768/1200px 宽度下，无关闭按钮和主要操作被横向裁切。
- [ ] 在 360/480px 高度下，侧栏底部入口和搜索结果均可滚动到达。
- [ ] 正文字号 12px 和 32px、侧栏展开和收起组合下，列表内容不重叠。
- [ ] 长书名、长书源名、长章名具有明确的省略或换行策略。

### 8.3 流程与状态

- [ ] 空书架可以直接进入书源导入和在线搜索。
- [ ] 新增但未阅读的书通过续读进入第 1 章。
- [ ] 删除取消不改变数据；保存失败保留草稿、选择和当前位置。
- [ ] 搜索无结果与搜索失败具有不同文案和恢复路径。
- [ ] 设置面板关闭后，不残留未保存的主题预览。

### 8.4 异步与数据归属

- [ ] A 书加载或下载时切换到 B 书，B 的正文、缓存点、进度和通知不受 A 回包影响。
- [ ] 预览超时后的迟到成功不会覆盖用户之后打开的书或关闭新面板。
- [ ] 暂停、继续、取消始终作用于原任务，而不是当前恰好打开的另一本书。

### 8.5 视觉与可访问性

- [ ] 全部预设、地域、节气、节日主题通过正文、次要文字、强调色和新增状态色测试。
- [ ] `dangerFg/danger` 与 `success/chromeBg` 的普通文字对比度均不低于 4.5:1。
- [ ] 小控件满足 24×24px 最低目标或对应间距例外，粗指针目标足够大。
- [ ] 信息状态不只依赖颜色表达，当前、半选、失败、下载状态均有文字或形状辅助。
