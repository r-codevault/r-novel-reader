### 1.1 原始需求复述

现有 VS Code 扩展 `r-novel-reader` 已完成主体功能，但设计评审指出 12 项体验基础缺失，集中在四类：键盘主链路不完整、浮层与响应式基础不稳、关键流程缺少一致终态、部分状态色与小控件未达可读可操作基线。本次要求把这 12 项落成**可验收的增量需求**，并明确必要联动；不重做产品，不改现有阅读主流程的信息架构。

### 1.2 与现有需求的边界

- **保留**：左侧导航—居中纸面—底部状态栏布局、统一浮层互斥规则、主题令牌体系、章内位置恢复、笔记定位原文链路、在线搜索暂停/继续/取消。
- **仅增量**：交互可达性、焦点交接、响应式收敛、终态一致性、状态色令牌、控件尺寸与名称。
- **禁止**：在本次任务中重写 `reader.css` 的结构性设计、替换主题美术方案、引入组件库、修改产品代码以外的文档（本 PRD 为唯一新增交付物）。

## 2. 背景与目标

### 2.1 背景

评审结论明确：问题不在视觉风格，而在体验基础。以下现状已核实：

- `webview/reader/reader.css:4-9`：`--ui-font` 由 `--font-size`（正文字号）推导，UI 字号被正文字号绑架。
- `webview/reader/reader.css:540-559`：`#shelfPopup` 等浮层 `width:max-content; min-width:380px`，在 400px 视口下右缘溢出（左缘 64px + 380px = 444px）。
- `webview/reader/App.vue:70-73`：`openOnly()` 只切布尔值，不移动焦点；`App.vue:687-713`：Esc 关闭后 `blurActiveElement()` 主动清焦点。
- `src/extension.ts:1426-1440`：`showSourcesPanel()` 在空书架时弹「请先打开一本书」，而 `openEmptyReader(tab)`（`extension.ts:962-969`）已支持空阅读页 + 指定抽屉，能力已存在但未被使用。
- `src/extension.ts:1779-1790`：`resumeCurrent` 在无进度时回退 `novel.chapters.length - 1`（末章）。
- `webview/reader/components/SettingsPanel.vue:304-312`：页面宽度档位按钮文案直接是 `33.33% / 55.55% / 66.66% / 77.77%`（`pctText()`），工程参数直出。
- `SettingsPanel.vue:192-197`：主题预设为不可聚焦的 `<span class="sp-dot">`，名称只靠 `title`。
- `src/settings.ts:214-227`：深色主题 `danger: #ff9d93`，当前配白字对比度 2.00:1；代码库中不存在 `dangerFg` / `success` 令牌。
- `webview/reader/components/SourceSearchView.vue:308-333`：失败只显示数量与源名串，无错误类型/原因/重试入口；无「成功但无结果」与「失败导致无结果」区分。

### 2.2 产品目标

1. **核心任务纯键盘可完成**：打开书籍、跳章、预览搜索结果、新建/编辑/删除笔记、关闭浮层全链路不依赖鼠标，且焦点不丢失。
2. **状态与归属永远可信**：任何异步结果只作用于发起它的书与请求；任何写操作都有明确的「进行中 → 成功/失败」终态且就地可见。
3. **弱环境不降级**：窄屏（320px 宽）与矮屏（360px 高）下无不可达区域；大字号（32px）不撑破管理面板；状态色达到 4.5:1 普通文字对比度。

### 2.3 成功度量（可测）

| 指标 | 目标 |
| --- | --- |
| 纯键盘任务链 | 5 步链（打开书→跳章→搜索预览→新建笔记→保存）100% 通过，无 Tab 陷阱、无焦点落地到 `body` |
| 串书类缺陷 | A/B 切书场景下，A 的迟到回包影响 B 的正文/进度/通知的次数 = 0 |
| 横向裁切 | 320/400/576/768/1200px 宽度下，关闭按钮与主要操作的 `getBoundingClientRect().right <= innerWidth` 全部成立 |
| 纵向可达 | 360/480px 高度下，侧栏最后一项与搜索结果最后一条可滚动到视口内 |
| 对比度 | 全部预设/地域/节气/节日主题：`dangerFg/danger >= 4.5`、`success/chromeBg >= 4.5` |
| 触控目标 | 书源复选框、图标按钮有效点击区域 `>= 24x24` CSS px；粗指针 `>= 40x40` |

## 4. 范围与非目标

### 4.1 范围内

- 12 项问题的交互、可访问性、响应式、状态与视觉令牌改动。
- 为上述改动所必需的联动：命令入口（首次书源搜索、续读）、消息协议字段（请求/书籍归属）、主题令牌与自动对比度测试、现有测试脚本补充。
- 受影响文案的同步（页面宽度档位名、书源空态文案、失败明细文案）。

### 4.2 非目标

1. 不改「左侧导航—居中纸面—底部状态栏」布局与主题美术方案。
2. 不把浮层改为模态对话框，不引入焦点圈禁与背景 `inert`。
3. 不引入 UI 组件库或替换原生 CSS 方案。
4. 不重构在线搜索、解析引擎、离线存储的既有业务逻辑（仅增加归属标识与终态回包）。
5. 不改摸鱼模式伪装策略；仅当其复用阅读页快捷键时保证不冲突。
6. 不做独立 UI 缩放设置项（保留为后续可选项，见 R4-02）。
7. 不做移动端/触屏独立布局；仅保证粗指针目标尺寸。

## 5. 用户故事

1. **键盘用户**：As a 只用键盘的用户，I want 用 Tab/Enter/方向键完成「打开书籍 → 跳章 → 搜索预览 → 新建并保存笔记」，so that 不被迫切鼠标也能读完一本书并留下笔记。
2. **屏幕阅读器用户**：As a 屏幕阅读器用户，I want 打开浮层后焦点进入浮层标题、关闭后回到触发按钮，so that 我不会丢失当前上下文、也不会被困在不可命名的控件里。
3. **窄窗口用户**：As a 把 VS Code 拖到半屏/窄栏的用户，I want 浮层在 320px 宽度下完整可见、关闭按钮不被裁切，so that 我能在分屏编辑时继续阅读。
4. **大字号用户**：As a 把正文字号调到 32px 的用户，I want 书架/书源/笔记面板的字号保持紧凑且行高自适应，so that 放大正文不会让管理面板撑爆。
5. **弱网/快速切书用户**：As a 在网络差时快速切书的用户，I want A 书的迟到回包不影响我当前打开的 B 书，so that 我看到的书名、正文、进度和下载状态永远属于同一本书。
6. **触屏/鼠标用户**：As a 习惯鼠标或触屏的用户，I want 关键操作不必先悬停才发现、点击区域足够大，so that 我能稳定点中「更多」「启用书源」这类小控件。

## 6. 需求池

> 图例：**必须**＝P0 阻断项；**应该**＝P1；**可以**＝P2。每条需求均给出可验证验收标准。

### 6.1 P0-1 键盘主链路（对应问题 1）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R1-01 | 目录分卷与章节条目**必须**改为可聚焦语义：单一主动作条目使用原生 `<button type="button">`，保留现有行样式 | P0 | Tab 可依次到达每个分卷头与章节；Enter/Space 均可触发跳章；视觉与现有 `div` 行一致（类名与布局不变） |
| R1-02 | 分卷展开按钮**必须**带 `aria-expanded` 与 `aria-controls`；当前章**必须**带 `aria-current="true"`（或 `page`） | P0 | 屏幕阅读器读出「已展开/已收起」与「当前章节」；展开状态随交互实时更新 |
| R1-03 | 书架条目、历史条目、搜索结果行**必须**采用「行容器 + 独立主按钮 + 操作按钮组」，禁止按钮嵌套按钮 | P0 | 键盘 Tab 遍历顺序为 行主按钮 → 该行操作按钮；不出现 `button` 内含 `button`；Enter 触发主按钮（打开/预览） |
| R1-04 | 书架/历史中当前书籍**必须**有 `aria-current`；行内删除等危险入口**必须**为独立可聚焦按钮且名称含书名 | P0 | 读出「删除《书名》」；Tab 可到达删除按钮 |
| R1-05 | 正文段落**必须**提供独立「添加/查看笔记」按钮，且**不得**把每个段落都放进 Tab 序列（不逐段 `tabindex="0"`） | P0 | 默认状态下 Tab 序列中不存在段落停靠点；正文区提供可聚焦的「笔记模式」入口（见 R1-06）后，段落按钮可达 |
| R1-06 | 笔记模式**必须**提供不依赖鼠标的入口（工具条可聚焦开关 + 一个可配置/固定快捷键），段落按钮采用 roving tabindex（同组仅一个 `tabindex="0"`，方向键移动，`tabindex="-1"` 供其余） | P0 | 键盘：开启笔记模式 → Tab 进入当前段按钮 → 方向键跨段 → Enter 打开编辑器；关闭笔记模式后段落按钮退出 Tab 序列，鼠标悬停仍可显示 |
| R1-07 | 笔记组头**必须**拆为并列控件：展开按钮（`aria-expanded`）、原生复选框（`<input type="checkbox">`）、删除按钮；半选**必须**用原生 `indeterminate` 或 `aria-checked="mixed"` | P0 | Tab 顺序 展开 → 复选框 → 删除；全选/半选/未选三态可被读屏区分；Space 切换勾选 |
| R1-08 | 端到端键盘链**必须**通过：打开书籍 → 目录跳章 → 搜索结果预览 → 新建笔记 → 编辑并保存笔记 | P0 | 一次不触碰鼠标完成全链；过程中 `document.activeElement` 从未变为 `body`；无 Tab 陷阱（Shift+Tab 可逆序返回） |

### 6.2 P0-2 异步请求归属（对应问题 2）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R2-01 | 在线章节请求**必须**在发起前捕获书籍引用（`const novel = this._novel`），结果只写回捕获的对象，禁止回包时重读 `this._novel` | P0 | 代码检查：请求闭包内不出现"回包后读 `this._novel`"的写法；A→B 切书后 A 回包不改变 B 的 `chapters`/`chapterIndex` |

## 7. 交互规则

### 7.1 焦点与浮层

1. 打开浮层：保存 `document.activeElement` → 显示浮层 → `nextTick` 聚焦顺序为「标题（可聚焦时）→ 关闭按钮 → 首个主要控件」。
2. 关闭浮层：恢复保存的触发元素；触发元素已不存在时按 fallback 顺序「对应侧栏菜单项 → 正文区容器」。
3. 浮层为非模态：允许 Shift+Tab 离开，不禁用背景，不加 `inert`。
4. Esc 分层：第 1 层内部下拉/子菜单 → 第 2 层当前浮层 → 第 3 层侧栏展开态。每层关闭后焦点回到该层触发控件，**禁止** `blur()` 丢焦点。
5. 浮层互斥保持：打开新浮层即关闭其余浮层，焦点移交新浮层。

### 7.2 键盘任务流

| 任务 | 键盘路径 |
| --- | --- |
| 打开书籍 | Tab 到书架条目主按钮 → Enter |
| 跳章 | 目录浮层 → Tab 到分卷（Enter 展开）→ Tab 到章节 → Enter |
| 搜索预览 | 书源面板 → 输入关键词 → Tab 到结果行主按钮 → Enter 预览 |
| 新建笔记 | 正文「笔记模式」开关（Enter）→ Tab 到当前段按钮 → Enter → 输入 → Ctrl+Enter/保存按钮 |
| 编辑/删除笔记 | 笔记浮层 → 组头展开/勾选/删除 → 条目「更多」→ 编辑或删除 |
| 危险批量删除 | 进入管理模式 → 勾选 → 「删除所选」→ 确认框（数量+对象）→ Enter 确认 → 成功退出 |

### 7.3 正文段落笔记模式

- 默认：段落按钮仅在鼠标悬停或所在段落已有笔记时可见，**不进入** Tab 序列（`tabindex="-1"`）。
- 笔记模式开启：正文容器加 `data-note-mode="on"`，可视段落内按钮可聚焦，采用 roving tabindex（同组仅 1 个 `tabindex="0"`，↑/↓ 或 ←/→ 在同组移动）。
- 关闭笔记模式：清除 roving 状态，段落按钮回到 `tabindex="-1"`，焦点回到模式开关。
- 已有笔记的段落：始终显示「查看笔记」标记（不只依赖颜色）。

### 7.4 危险操作

```
触发 → 管理模式 → 选择 → 确认框（数量 / 对象 / 空间 / 可恢复性）→
  [取消] → 关闭确认框，保留选择与上下文
  [确认] → 按钮进入「操作中…」→
      成功 → 关闭确认框 → 清空选择 → 退出管理模式 → 就地成功提示（status）
      失败 → 关闭确认框 → 保留选择/草稿 → 就地错误提示（alert）+ 重试入口
```

### 7.5 页面宽度档位

| 内部值 | 显示名 | 辅助说明 |
| --- | --- | --- |
| `0.3333` | 窄 | 视口宽度 33.33% |
| `0.5555` | 标准 | 视口宽度 55.55% |
| `0.6666` | 宽 | 视口宽度 66.66% |
| `0.7777` | 特宽 | 视口宽度 77.77% |
| 自定义 | 自定义 | 480–4000px，超窗口横向滚动 |

档位内部数值不改，不涉及设置迁移；仅改展示层。

### 7.6 状态提示层级

| 场景 | 语义 | 位置 |
| --- | --- | --- |
| 普通进度（搜索/下载） | `role="status" aria-live="polite"` | 发起面板内 |

## 9. 回归风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| `reader.css` 大范围改动（浮层宽度、行高、字号变量）影响所有面板视觉 | 中高：布局回归面广 | 逐检查点截图对比；保留原类名与 DOM 层级，优先改属性值而非结构 |
| 移除 Esc 的 `blurActiveElement()` 可能引入「鼠标点击后按键出现焦点框」的视觉回归 | 中：这是当初加 blur 的原因 | 用 `:focus-visible` 语义处理，仅在键盘导航时显示焦点环；改动后专项复测鼠标点击 + 按键场景 |
| 条目改为 `<button>` 可能继承默认样式/表单行为 | 中：容器内误触发表单提交或样式漂移 | 统一 `type="button"` + 现有类名；禁止按钮嵌套 |
| 请求归属改造触及 `readerPanel.ts` / `extension.ts` / `App.vue` 三处消息链路 | 高：可能破坏现有在线书/离线下载 | 保留旧字段名向后兼容一个版本；新增 A/B 切书回归测试 |
| 空书架直达书源抽屉改变 `showSourcesPanel()` 行为 | 中：影响首次使用与命令面板 | 保留 `openDrawerAt('source')` 作为有书路径；空态路径新增分支 |

| README 与设置项描述涉及百分比档位（`README.md:283`） | 低：文案不一致 | 档位名称变更后同步 README；README 已有未提交改动，需与主理人确认是否一并更新 |
